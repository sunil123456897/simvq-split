# Бэклог архитектурных идей (`Calcite v3+`)

Живой список перспективных идей для будущих одноосевых абляций (каждая идея проверяется строго через `Gate 1–3`, `2*sigma` порог и правило `Via Negativa`).

---

## 1. DeepCrossAttention (DCA) — динамический роутинг по глубине слоёв

- **Источник:** Mike Heddes et al., Google Research, *DeepCrossAttention: Supercharging Transformer Residual Connections* (`arXiv:2502.06785`, ICML; блог `research.google/blog/supercharging-transformer-residual-connections/`).
- **Суть механизма:** замена плоского суммирования $x_l = x_{l-1} + F_l(x_{l-1})$ на обучаемый, зависящий от входа роутинг по всем предыдущим слоям глубины (статическая база + токен-зависимая проекция `b_t + w_t(x)` / depth-wise cross-attention). По данным статьи: ускорение сходимости до `3x` или сокращение глубины до `-29%` при `< 0.2%` лишних параметров.
- **Почему сильная связка именно с `Calcite`:**
  1. У `Calcite` гетерогенная глубина (`z_in`, `cortex_pre SWA`, `Crystal`, `Woodbury`, `EpistemicSlots`, `mid_mlp`, `cortex_post`). Сейчас все разнородные сигналы сливаются в одну сумму `h + delta`, вызывая размытие и требуя защитных тормозов `-1.8` на вентилях. С DCA каждый блок динамически тянет нужную смесь слоёв (прямой `z_in` для точного копирования байтов/кода, `Crystal` для `S_5`, `Woodbury`/`Slots` для фактов и перезаписи).
  2. **`+0` байт к $O(1)$ стриминговому кэшу:** ось внимания — глубина (`8–15` узлов), а не длина последовательности (`32K`). В `CalciteStreamEngine` состояние между чанками не растёт.
  3. **Малый накладной расход на обучении:** бэкбон работает поверх чанков (`T / 4.6`), поэтому хранение стека активаций глубины в `4.6x` дешевле, чем в байтовом трансформере.
- **Инварианты реализации (до запуска):**
  - Инициализация строго в тождественную остаточную связь (динамическая проекция `w_t(x) = 0`), чтобы на старте сохранить `Gate 2` `init-std ratio = 1.0`.
  - Крошечные веса роутинга глубины (`< 0.2%`) исключить из `2-bit LUT` квантования (держать в FP16/BF16, как `RMSNorm` и вентили).
- **План проверки:**
  - Сначала быстрая одноосевая ячейка `M5_dca_depth_routing` на `5M` (`Val BPB`, `OW6`, скорость сходимости).
  - Основной ожидаемый выигрыш — на более глубоких тирах **`25M` (`12–13` узлов глубины)** и **`85M` (`15+` узлов глубины)**.
  - Ортогонально к `M1_sparse_woodbury` и `M2_epistemic_slots` (чинит вертикальное размытие по глубине, не заменяет горизонтальную ёмкость памяти).

## 2. Идеи из `CircularEP` для `Calcite-6 / UEBR System-2` (без медленного EP в `System-1`)

- **Источник:** Tommaso Salvatori, Matteo Forasassi, *Circular Predictive Coding Unlocks Effective Depth* (`arXiv:2611.27610v1`, 20 Nov 2026; код `github.com/rel-int/CircularEP`).
- **Что НЕ берём (`Via Negativa`):**
  - Не тащим `Equilibrium Propagation (EP)` и `20`-шаговую релаксацию Anderson в `Calcite System-1`: на цифровых GPU (Table 6, WikiText-103 `8.71M`, `L = 128`, `FP32`) EP в **`15.2x` медленнее** обычного `DEQ` (`3.8 h` vs `0.25 h` на H100 из-за `400` Heavy-Ball HVP-итераций), требует жёсткого `spectral cap < 1` и ломает наш быстрый `2-bit LUT` CPU-стриминг.
- **Три механизма, которые стоит перенести в `experiments/uebr_system2/` (поверх быстрого `0`-BPTT Cholesky/DEQ-аджоинта):**
  1. **Recursive Multi-Stage Equilibrium с `detached carry` (`Algorithm 1`, ур. 9):**
     - `S = 4..16` последовательных стадий общими весами (`x_hat_L = g_{L-1,L}(x_{L-1}) + e(u) + W_a a`), где каждая стадия тёплым стартом берёт равновесный ответ прошлой (`a ← x*_L`, detached) и супервизируется отдельно (deep supervision без BPTT).
     - В статье на Sudoku-hard (`18k` тестов) дало **`10x` сжатие параметров** (`105K` против `1.1M`) и резкий рост на глубоких цепочках вывода (`depth >= 15`: `18% -> 45%` single-view).
  2. **Oracle-free отбор по `Self-Cost` + Multi-View test-time compute:**
     - Параллельный прогон `K` стартов/перестановок задачи с выбором решения по минимальной собственной кросс-энтропией уверенности ($C_{\text{self}} = -\frac{1}{N}\sum \max_c \log\text{softmax}(x_{\mathcal{O},p})_c$) без единого жёсткого правила задачи и без внешнего оракула (на Sudoku-hard: `85.7% -> 99.3%`, в `0.2%` от оракула).
     - Прямой кандидат для test-time compute поверх связки `Calcite System-1 + UEBR System-2`.
  3. **`Dual Readout` (`d(0.5*(x_{L-1} + x_L))`) + мягкий контроллер локального спектрального радиуса $\rho(J_f)$:**
     - Чтение сразу с двух узлов цикла (`+0` параметров, `+1.9..2.1%` качества) и адаптивный контроль локального $\rho(J_f)$ вместо жёсткого зажима всех матриц в `< 1` (Appendix A.1), чтобы не душить выразительность `UEBR` при сохранении устойчивого равновесия.

## 3. Temporal Residual (TR) — отдельный переносной поток `B` для скрытого рассуждения (Приоритет для ретрофита)

- **Источник:** Ziyang (Jack) Cai, Xingyu Zhu, Sanjeev Arora (Princeton University), *The Temporal Residual: Fast and Effective Retrofitting of Latent Feedback into Pretrained Language Models* (`2026`).
- **Суть механизма:** второй параллельный резидуальный поток `B`, который переносится между позициями/чанками ($u = r_A A + r_B B$, $y = f(u)$, $A \leftarrow A + y$, $B \leftarrow B + s_B y$, $B_0(t) = \phi(B_L(t-1))$).
  - **`0` новых матриц:** только `3` скаляра на подслой (`r_A=1, r_B=0, s_B=1` на старте) + одна `RMSNorm` $\phi$ (`~500` параметров на `25M` `Calcite`, нулевое влияние на размер `2-bit LUT`).
  - **Точный ретрофит:** при `r_B = 0` модель на шаге `0` тождественна обученному чекпоинту; включается только на коротком post-training / SFT по задачам рассуждения (не замедляет pretrain).
  - **Влияние на `CalciteStreamEngine`:** ровно **`+1` вектор `d_model`** (`512 B` на `5M`, `896 B` на `25M`) — строгое сохранение $O(1)$ RAM.
- **Почему это чинит провал `A4_latent_feedback` из Фазы L:**
  1. Отдельный поток `B` вместо вливания в единственный входной поток `z_in` (где `Recycler`/`FBT` теряют `60–100%` эффекта).
  2. Правильный рецепт обучения: **`4–6` параллельных проходов Якоби, но `backward` только через последние `2`** (ранние под `no_grad`), иначе модель переобучается под `K = 2` и ломается при точном декодинге (`K -> inf`). Оценка качества — строго по loss при большом `K >= 8`, а не по минимальному `K = 2`.
- **План проверки (ночной эксперимент):**
  - Взять готовый обученный чекпоинт `Calcite v2 / v3` (`5M` или `25M`), навесить `Temporal Residual` (`r_B = 0`) и сделать короткий SFT-ретрофит на смеси `S_5 (k=2..16)` + `Overwrite` + `GSM8K`/математика (`4–6` проходов, `last-2 backprop`), сравнить на точном декодинге и `S_5 k=8/16` с контролем без `TR` (и при равном compute).
  - При переходе к RL (`GRPO`) обязательно сохранять и проигрывать (`replay`) сэмплированные состояния `B_0(t)` (без replay RL обваливается).

## 4. `Gated DeltaNet-2` — разделение вентилей стирания и записи в `Woodbury` (Высокий приоритет)

- **Источник:** Ali Hatamizadeh, Yejin Choi, Jan Kautz (NVIDIA), *Gated DeltaNet-2: Decoupling Erase and Write in Linear Attention* (`arXiv:2605.22791`, 2026).
- **Суть механизма:** вместо одного скаляра $\beta_t$ на стирание и запись (как сейчас в `calcite_v2/woodbury.py`) и скалярного затухания $\gamma_t$, вводятся **поканальные независимые вентили** затухания $\alpha_t$, стирания $b_t$ и записи $w_t$:
  $$M_t = M_{t-1}\,\mathrm{Diag}(\alpha_t)\,(I - k_t (b_t \odot k_t)^\top) + (w_t \odot v_t) k_t^\top$$
- **Почему сильная связка с `Calcite`:**
  - **`+0` байт к $O(1)$ RAM**, всего `3` лёгкие проекции `d_model -> H*D`, прямой апгрейд поверх `M1_sparse_woodbury`.
  - Позволяет точечно стирать устаревший атрибут сущности по ключам, не затирая ортогональные каналы значений (бьёт прямо по потолку `Overwrite Long`).

## 5. `Attention Residuals (AttnRes)` — лёгкий softmax-роутинг по глубине слоёв (Проще `DCA`)

- **Источник:** Kimi Team (Moonshot AI), *Attention Residuals* (`arXiv:2603.15031`, март 2026); смежная линия — DeepSeek *mHC: Manifold-Constrained Hyper-Connections* (`arXiv:2512.24880`).
- **Суть механизма:** упрощённая и более дешёвая версия `DCA`: у каждого слоя $l$ есть один обучаемый вектор-запрос $q_l \in \mathbb{R}^{d}$, вычисляющий `softmax` по нормализованным выходам всех предыдущих слоёв:
  $$h_l = \sum_{i=0}^{l-1} \alpha_{i \to l} v_i, \qquad \alpha_{i \to l} = \mathrm{softmax}_i\big(q_l^\top \mathrm{RMSNorm}(v_i)\big)$$
- **Почему сильная связка с `Calcite`:**
  - **`+0` байт к постоянной $O(1)$ RAM** стриминга, `< 0.1%` параметров, проще в реализации и стабильнее в `2-bit LUT`, чем `mHC` (без Sinkhorn-проекций на многогранник Биркгофа).
  - Сразу разводит сигналы гетерогенных слоёв (`z_in`, `SWA`, `Crystal`, `Woodbury`, `EpistemicSlots`) и позволяет протестировать отказ от легаси-тормозов `-1.8`.

## 6. `Canon Layers` — 4-таповое горизонтальное смешивание внутри чанковых блоков `SWA/MLP`

- **Источник:** Zeyuan Allen-Zhu (Meta), *Physics of Language Models: Part 4.1, Architecture Design and the Magic of Canon Layers* (`NeurIPS 2025`, `arXiv:2512.17351`).
- **Суть механизма:** ультралёгкие каузальные 4-таповые depthwise-свёртки (`Canon-A/B/C/D`), добавляемые как горизонтальные остаточные связи прямо перед `qkv` и `SwiGLU` в каждом блоке. В статье радикально усиливают слабые/линейные миксеры и глубину рассуждений почти за ноль FLOPs.
- **Почему сильная связка с `Calcite`:**
  - На уровне **байтов** ровно этот приём (`A1b_byte_mixer_2scale`) уже дал нам `-0.1488 BPB` (`26.1*sigma`).
  - Внутри **чанковых** `LocalSWABlock` он стоит всего `3 * d_model * 2 B` (`1.5 KB` на блок = `+6 KB` на `5M`), сохраняет `O(1)` стриминг и усиливает короткий контекст `L = 512` без расширения окна `SWA` (`W = 8` сохраняется, `S_5` не ломается).

## 7. Оптимизатор `Muon / NorMuon` (ускорение локальных ночных прогонов до `1.5x–2.0x`)

- **Источник:** Keller Jordan; Liu, Su et al., *Muon is Scalable for LLM Training* (`2025`); *NorMuon* (`2026`).
- **Суть механизма:** `5` итераций ортогонализации Ньютона–Шульца на моментуме всех скрытых 2D-матриц (`SWA`, `SwiGLU`, `chunker`), оставляя `AdamW` на `tok_emb`, `lm_head`, 1D-параметрах (`RMSNorm`, bias) и `Woodbury` (`wd=0.0`, `0.35x LR`).
- **Зачем нам:** `0` изменений в архитектуре и `0` цены на инференсе, но потенциально в `1.5x–2.0x` быстрее сходимость на локальной `RTX 5060` — за ту же ночь модель добирает эквивалент вдвое большего бюджета данных.

## 8. Чисто-тензорный `Engram` (хэш-таблица байтовых `2–4`-грамм в декодере)

- **Источник:** линейка *Engram / Tensorized N-gram Memory* (`2025–2026`).
- **Суть механизма:** полиномиальный rolling hash по последним `2–4` байтам `token_ids` (чистая векторная арифметика `torch.remainder`, без `dict`/`re`/`ast`) → маленькая таблица `nn.Embedding` (`4K–16K` слотов × `d_engram`), подмешиваемая в байт-декодер.
- **Зачем нам:** разгружает `2-bit LUT` бэкбон от тупого запоминания частой орфографии, UTF-8 префиксов и синтаксиса Python/JSON, напрямую сокращая разрыв `~0.20 BPB` с `RoPE` на `L = 512` при **`+0` байт динамического состояния** (`O(1)` RAM).

---

## Что осознанно отсеяно (`Via Negativa` — не тратить ночь)

- **`Titans` / `ATLAS` (`2025`):** внутренний градиентный спуск по MLP-памяти прямо на инференсе — ломает скорость CPU-стриминга и усложняет `2-bit LUT`.
- **Полный `mHC` (`arXiv:2512.24880`):** многопоточные Sinkhorn-проекции избыточны на `5M–25M`, пока не проверен более простой `AttnRes`.
- **`BitNet v2` (`W1.58A4` Hadamard-активации):** оптимизировано под специализированный батчевый инференс A4; наш текущий приоритет — качество BPB и `2-bit LUT` веса.

---

## Рекомендуемая очередь для ночного автономного прогона (`RTX 5060`)

1. **После завершения `M0–M4`:** зафиксировать победителей Фазы M и прогнать их комбо (`M_combo`).
2. **Быстрая 5M-серия №2 (`~30–40 мин`):** одноосевые проверки **`M5_attnres`** (`AttnRes` по глубине), **`M6_deltanet2_woodbury`** (разделённые `b_t / w_t / alpha_t` поверх `M1`), **`M7_canon_chunks`** (`Canon 4-tap` внутри `LocalSWABlock`), **`M8_muon_opt`** (`Muon` на 2D-матрицах).
3. **Когнитивный стресс-тест победителя (`S_5` + `Overwrite Long` + `Needle 2K/8K`):** прогон лучшей комбинации `Calcite v3` на достаточном когнитивном бюджете (`1,600–2,000` шагов) + тест **ретрофита `Temporal Residual (TR)`** (`4–6` проходов Якоби, `last-2 backprop`) поверх обученного чекпоинта.
